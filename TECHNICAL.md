# Слойка (Slojka) — техническое описание

AI-first десктопный графический редактор в духе Photoshop для Linux
(первичная платформа — Debian 11). Локальный WebGL2-движок пиксельного
редактирования, слои и маски, собственный формат файлов, локальное
удаление фона (ISNet/ONNX в renderer), опциональный локальный SAM 2.1
для умного выделения, хаб облачной генерации polza.ai и встроенный
AI-ассистент (Claude Code), управляющий редактором через MCP.

Документ описывает архитектуру, все подсистемы, форматы, протоколы,
горячие клавиши и известные нюансы по состоянию репозитория (~57 коммитов,
~23 300 строк TS/TSX/Python/CSS в 120 файлах).

Ключевые инварианты:

- **Ядро редактора никогда не зависит от sidecar.** Все AI-функции
  опциональны: без Python и без ключа polza.ai редактор полнофункционален,
  соответствующие кнопки серые с подсказкой.
- Все протоколы типизированы: IPC описан в preload с типами, модель
  документа — общий TypeScript в `packages/shared`.
- Бренд — одна константа `BRAND` (`packages/shared/src/branding.ts`):
  id `slojka`, имя «Слойка», расширение `.slojka`. Переименование тривиально.
- Electron 42.5.2 — проверен на Debian 11 (glibc 2.31); мажор не поднимать
  без теста на целевой машине.
- Русский язык — основной, английский — зеркальный (`Mirror<typeof ru>`
  гарантирует паритет ключей на уровне типов + юнит-тест).

## 3. Модель документа (packages/shared/src/document.ts)

Пиксели живут в движке (текстуры GPU); JSON-модель хранит структуру и
параметры и сериализуется в `manifest.json` формата `.slojka` как есть.

```ts
DocumentJson { schema: 1, width, height, layers: LayerJson[], activeLayerId }
LayerBase    { id (uuid), name, visible, opacity 0..1, blendMode,
               clipped, hasMask, styles?: LayerStyles }
RasterLayerJson = LayerBase & { kind:'raster', smart?: {srcW, srcH, transform} }
TextLayerJson   = LayerBase & { kind:'text', text: TextParams }
```

- **Blend-режимы** (8): normal, multiply, screen, overlay, soft-light,
  darken, lighten, add (Linear Dodge). Формулы — W3C compositing spec,
  считаются на непремультиплицированных цветах.
- **SmartTransform** `{cx, cy, dx, dy, sx, sy, rot}` — модель
  `q = R·S·(p−c) + c + d`; поворот в радианах.
- **TextParams**: content, fontFamily, fontStyle ('normal'/'bold'/'italic'/
  'bold italic'), fontSize, color, letterSpacing, lineHeight, align,
  x/y (якорь), boxW/boxH (paragraph text), rotation (градусы),
  `styleRanges?: TextStyleRange[]` — стили фрагментов.
- **TextStyleRange** `{start, end, color?, fontFamily?, fontStyle?, fontSize?}`
  — полуинтервалы [start, end) по индексам content; заданные поля
  перекрывают базовые. Утилиты: `setStyleRange` (нарезка/наложение/слияние
  диапазонов), `adjustStyleRanges` (сдвиг диапазонов при правке текста через
  диф общий-префикс/суффикс: набор внутри фрагмента расширяет его, удаление
  обрезает). Покрыты юнит-тестами.
- **LayerStyles**: dropShadow, innerShadow (ShadowStyle), outerGlow
  (GlowStyle), stroke (StrokeStyle: color, opacity, size 1..50 — внешняя
  обводка), colorOverlay, gaussianBlur, motionBlur.
  - ShadowStyle: color, opacity, distance (px), angle (°), size (радиус
    размытия, px), spread (расширение-дилатация, px 0..50).
  - MotionBlurStyle: distance (длина смаза, px 0..300), angle (°).
  - ColorOverlayStyle: color, opacity — видимая часть слоя перекрашивается.
- Лимиты холста: 1..8192 px, предупреждение с 4096, по умолчанию 2048².

## 4. WebGL2-движок (packages/engine)

### 4.1 Базовые примитивы GL

- **Texture**: RGBA8 premultiplied или R8 (маски/выделения); CLAMP_TO_EDGE,
  LINEAR (+`setMagFilter('nearest')` на большом зуме). Для R8 критичны
  `UNPACK_ALIGNMENT/PACK_ALIGNMENT = 1`.
- **Fbo**: framebuffer с автосинхронизацией viewport под размер текстуры
  (`bind()`), переприкреплением (`attach()`), чтением пикселей в конвенции
  документа (строка 0 = верх, совпадает с texel-строками).
- **Quad + VERT**: один вершинный шейдер, позиционирование через
  `uRect` (NDC x0, y0, w, h).

### 4.2 Шейдеры (24)

| Шейдер | Назначение |
|---|---|
| FRAG_BLEND | композит слоя: 8 blend-режимов + маска + clipping + opacity |
| FRAG_DAB / FRAG_DAB_TIP | штамп круглой/текстурной кисти с hardness |
| FRAG_MERGE / FRAG_MERGE_MASK | вливание stroke-буфера в слой / в маску |
| FRAG_PRESENT | вывод на экран: шахматка прозрачности, пиксельная сетка от 8× |
| FRAG_EXTRACT | вырезание выделенного (для floating) |
| FRAG_PLACE | рендер smart-слоя из оригинала с трансформацией |
| FRAG_FLOAT | отрисовка плавающего фрагмента с трансформацией |
| FRAG_FILL / FRAG_COPY | заливка premult-цветом / копирование |
| FRAG_SHADOW_MASK | маска тени: альфа со смещением, инверсия для внутренней |
| FRAG_SHADOW_COLOR | колоризация маски тени (+клип по альфе для inner) |
| FRAG_SEL_COMBINE | булевы операции выделения (replace/add/subtract/intersect) |
| FRAG_THRESHOLD | мягкий порог (растушёвка→чёткий край; дилатация spread) |
| FRAG_INVERT | инверсия выделения |
| FRAG_GAUSS | сепарабельный гаусс по R8 (растушёвка, тени) |
| FRAG_GAUSS_RGBA | гаусс по premult-RGBA (стиль «Размытие по Гауссу») |
| FRAG_MOTION | размытие в движении: 65 выборок вдоль вектора в UV |
| FRAG_COLOR_OVERLAY | перекраска premult с сохранением альфы |
| FRAG_ANTS | марширующие муравьи по границе выделения |
| FRAG_JFA_INIT / FRAG_JFA_STEP | поле расстояний до края (jump flooding) |
| FRAG_DIST_SHAPE | дилатация/спад из поля расстояний (обводка, spread, свечение) |

Нюанс: FRAG_GAUSS_RGBA и FRAG_MOTION сэмплируют за краем документа
CLAMP_TO_EDGE (как Photoshop) — слой во весь холст не прозрачнеет по краям;
растворение краёв объекта дают его собственные прозрачные пиксели.

### 4.3 Композитор

Пинг-понг двух аккумуляторов (`accumA`/`accumB`): для каждого видимого слоя
`blendOnto(срцТекстура, opacity, mode, mask, clipBase)`. Обтравочные маски —
клип по альфе ближайшего не-clipped слоя ниже. До теней применяются
размытия слоя и наложение цвета (тени строятся по уже отфильтрованному
силуэту). Порядок стилей: гаусс → движение → наложение цвета → внешняя
тень (под слоем) → внешнее свечение (под слоем, screen) → сам слой →
плавающий фрагмент → внутренняя тень (поверх, клип по альфе).

### 4.4 Стили слоя — детали реализации

- **Тени/свечение** (`buildShadow`): маска альфы со смещением (uOffset в UV)
  → дилатация «Размер» (spread, px) → «Размытие» (size, px): сепарабельный
  гаусс → колоризация в premult RGBA. Пинг-понг R8-скретчей styleA/styleB.
  Свечение = distance 0 в режиме screen; внутренняя тень: инверсия альфы +
  клип результата по альфе слоя. **Внешняя обводка** = жёсткая дилатация
  без размытия, рисуется под слоем ближе всех к нему.
- **Поле расстояний (JFA)**: дилатация (spread, обводка) и спад свечения
  считаются по евклидову полю расстояний (jump flooding: init + log₂ N
  шагов 3×3, RG32F-скретчи с разрешением ≤ ~4 Мп, форма — в полном
  разрешении). Эффект идёт от края строго во все стороны, включая углы
  (прежний способ «гаусс 2·spread + порог 0.16» в углах не дотягивался —
  масса размытия там вчетверо меньше; закреплено селфтестами углов).
  Свечение — изотропный smoothstep-спад по расстоянию (ядро spread,
  спад size). Без EXT_color_buffer_float — фолбэк на гаусс+порог.
  Поле не зависит от радиусов и кэшируется отдельно (`doc.distField`,
  одна запись): тик ползунка размера/spread пересчитывает только проход
  «расстояние → форма», JFA гоняется лишь при изменении слоя.
- **Кэш и даунсемпл теней**: R8-маска тени кэшируется в
  `doc.styleMaskCache` по ключу «версия слоя + геометрия стиля» (цвет и
  непрозрачность — вне ключа: колоризация выполняется каждый кадр, это
  один дешёвый проход); радиусы > 12 px считаются на уменьшенном
  разрешении (фактор до 8, пул `doc.blurSmall`). Без этого live-настройка
  свечения/теней фризила: полноэкранный O(R)-гаусс на каждый кадр.
- **Размытия слоя**: кэш на слой (`blurTex`, ключ
  `${version}|${gaussR}|${motionD}|${angle}`), не используется во время
  штриха. Радиус > 12 px — **даунсемплированный путь**: фактор 2/4/8
  (`2^ceil(log2(r/12))`, смаз > 64 px → ≥2, потолок 8), каскадное
  уменьшение вдвое через пул `doc.blurSmall`, размытие уменьшенным радиусом,
  линейный апскейл. Это убирает фризы при перетаскивании размытых объектов
  (~70× меньше выборок на больших радиусах).
- **Размытие в движении учитывает поворот объекта**: эффективный угол =
  угол стиля + поворот smart-трансформации (рад→град) или текста.
- **Наложение цвета**: один проход `mix(src, premult(color, srcA), opacity)`.

### 4.5 Кисти и штрихи

- Pointer Events с давлением пера; коалесцированные события
  (`getCoalescedEvents`) для гладкости.
- Дабы по сплайну с интерполяцией позиции/давления, spacing в долях
  диаметра; «мокрый» stroke-буфер (R8) → merge в слой/маску на pointer-up —
  поведение непрозрачности как в Photoshop (opacity на штрих, flow на даб).
- Ластик — тот же путь с вычитанием альфы. Кисти выделения (add/subtract)
  пишут в маску выделения.
- Штрихи клипуются активным выделением.
- **Импорт кистей**: `.kpp` Krita (PNG c XML в tEXt-чанке — свой парсер
  чанков; size/spacing/opacity/flow/rotation) и `.abr` Photoshop (v1–2
  полностью, v6+ секция samp — сэмпловые типсы). Динамики движков не
  переносятся — своя универсальная модель кисти с pressure-кривыми;
  непарсибельные кисти пропускаются с отчётом. Текстурные типсы живут в
  реестре движка (`registerBrushTip`).

### 4.6 Выделения

- Одноканальная R8-маска (антиалиас и растушёвка first-class), три
  текстуры: selCur, selScratch, selShape.
- Инструменты: прямоугольник, овал, лассо (полигон), волшебная палочка
  (CPU flood-fill по допуску), кисти выделения, Ctrl+клик по миниатюре
  слоя (альфа слоя), Ctrl+A (по фактическим пикселям активного слоя),
  SAM (см. §8).
- Булевы операции: replace / add (Shift) / subtract (Alt) / intersect.
- **Живая подстройка**: пока «муравьи» активны, в панели опций доступны
  ползунки «Растушёвка» (гаусс) и «Расширить/Сжать» (гаусс+порог) с
  превью и фиксацией в историю (begin/preview/commit/cancelSelectionAdjust).
- **Муравьи**: edge-detect по «внутри, но сосед снаружи» с явной выборкой
  соседей в 1 экранный пиксель; анимированные полосы; за пределами
  документа считается «снаружи» (Ctrl+A рисует муравьёв по периметру).
  Анимация тикает ~10 к/с (не грузит GPU впустую).

### 4.7 Floating-трансформация и smart-слои

- `liftSelection()` вырезает выделенное в плавающую текстуру (floating) с
  резервом пикселей для undo; Enter/клик мимо — commit, Esc — отмена,
  Delete — удалить фрагмент.
- **Smart-слои** (Smart Object): пиксели рендерятся из оригинала полного
  разрешения (`source`-текстура) с трансформацией — перемещение,
  масштабирование и поворот без потерь, содержимое «за краем холста» не
  пропадает. Обычный растровый слой конвертируется в smart на лету при
  выборе инструмента «Перемещение» (`convertToSmart`); рисование по smart
  растеризует его.
- **Рамка трансформации**: 8 ручек (углы чётные 0..7). Масштабирование
  **якорное**: тянешь за ручку — растёт в её сторону, якорь — противоположная
  ручка `(h+4)%8`; компенсация смещения `d' = d + (a0 − a1)`; боковые ручки —
  одноосно; текст масштабируется от естественного верхнего левого угла.
- **Прилипание**: сдвиг — края/центр bbox к краям/центру документа;
  масштаб — «щелчок» на 100% и подгонка k, чтобы тянущаяся ручка легла на
  край/центр документа (`snapScaleAnchored`); поворот — к углам кратным 45°.
  Alt отключает прилипание.
- **Курсоры**: ручки — соответствующие resize-курсоры; зона поворота
  (снаружи возле угла, 26 px) — SVG-курсор «изогнутая стрелка», повёрнутый
  под ближайший угол рамки и доворачивающийся вместе с ней (кэш по углу с
  шагом 15°).

### 4.8 Текст

- Шрифты системы через `fc-list` в main-процессе (кэш);
  растеризация OffscreenCanvas → текстура; текст всегда редактируем
  (параметры в JSON).
- Многострочность (\n), перенос по словам в paragraph-боксе, трекинг,
  межстрочный интервал, выравнивание (left/center/right), поворот вокруг
  центра рамки, жирный/курсив.
- **Стили фрагментов** (как выделение символов в Photoshop): выделяете
  часть текста в поле панели — секция «Фрагмент» даёт свой цвет, размер,
  Ж/К и шрифт (с живым hover-превью). Отрисовка посегментная: строка
  режется на однородные куски, x накапливается по измеренной ширине
  каждого куска (letterSpacing учитывается), базовая линия общая.
  Диапазоны автоматически «едут» при правке текста (adjustStyleRanges в
  `engine.setTextParams`).
- Инструментом «Текст»: клик — point text, драг — paragraph text
  (фиксированная область с переносом и клипом по высоте), драг существующего
  текста — перемещение.

### 4.9 История (undo/redo)

Гибрид: структурные операции — команды do/undo над JSON-моделью;
пиксельные — снапшоты before-пикселей dirty-rect (readPixels + deflate
fflate). Бюджет памяти по умолчанию 256 МБ (настройка 64–2048 МБ,
`setHistoryBudgetMb`), вытеснение старых записей с dispose-хуками
(текстуры удалённых слоёв освобождаются, если больше не в документе).
Панель истории показывает подписи операций (i18n-ключи `history.*`),
клик — прыжок по стеку. Все правки MCP-ассистента идут через тот же
пайплайн и отменяемы.

### 4.10 Размер холста и кадрирование

`engine.resizeCanvas(width, height, dx, dy, label)`:

- (dx, dy) — куда попадает левый верх старого холста в новом
  (кадрирование = отрицательные значения);
- обычные растровые слои блитятся со смещением (`blitOffset`), маски
  дополняются белым (видимым);
- smart-слои и текст **перерисовываются из оригинала** со сдвигом
  трансформации/якоря — содержимое за старым краем «возвращается» при
  расширении;
- все служебные буферы документа пересоздаются под новый размер
  (`reallocDocBuffers`), выделение снимается, кэши размытий сбрасываются;
- undo восстанавливает старые текстуры целиком (пары старая/новая живут в
  замыкании истории, dispose освобождает неиспользуемые при вытеснении);
- лимиты: 1..8192 px; во время штриха операция игнорируется; floating
  предварительно коммитится.

UI: диалог «Изображение → Размер холста» (ширина/высота, якорь 3×3 — где
остаётся содержимое, предупреждение об обрезке) и **инструмент
кадрирования** (C): рамка с 8 ручками, затемнение снаружи, линии третей,
подпись размера, перемещение рамки целиком, Enter/двойной клик/кнопка —
применить, Esc — убрать; рамка может выходить за холст (это расширение).
Рамка сбрасывается при смене инструмента и переключении вкладок.

### 4.11 Вью и рендер

- Pan/zoom: колесо — зум к курсору, пробел/средняя кнопка/рука — панорама,
  Ctrl+0 fit, Ctrl+1 100%.
- Present: шахматка под прозрачностью, NEAREST от 3× (резкие пиксели),
  пиксельная сетка с 8× (как PS от ~800%).
- Линейки в пикселях документа, координаты курсора в статусбаре.
- `needsRender` экономит кадры: перерисовка только при инвалидации
  (муравьи — не чаще 10 к/с).
- Фолбэк без GPU: SwiftShader + предупреждение в статусбаре.

### 4.12 Самотесты движка (selftest.ts)

~30 пиксельных проверок на живом GL, гоняются в `npm run smoke`:
blend-режимы по фикстурам, кисть/ластик/undo, клип выделением, маска слоя,
текст (+цвет фрагмента, сдвиг диапазона при правке, увеличенный фрагмент
выше базового), муравьи, тень (+монотонность spread), floating,
гаусс/движение/даунсемпл/кэш/снятие, края холста не растворяются,
наложение цвета (100% и 50%), смаз с поворотом слоя, размер холста
(кадрирование → undo → расширение), замена пикселей слоя и оригинала
smart-слоя с undo (базис «Удалить фон»), ластик. Плюс smoke-уровень:
round-trip `.slojka` (0 расхождений), клипборд-хоткеи с переносом стилей,
smart-слой (сдвиг/возврат), опционально — сквозное удаление фона.

## 5. Electron-приложение

### 5.1 Main-процесс

- **Окно**: frameless, кастомный титлбар с меню (Файл/Правка/Изображение/
  Выделение/Вид) и window-controls; скрытое нативное меню держит
  акселераторы (нюанс X11: у frameless-окон акселераторы через нативное
  меню, action-id общие с кастомным титлбаром).
- **files.ts**: диалоги открытия/сохранения, чтение/запись файлов.
- **resProtocol.ts**: схема `slojka-res://` — локальная раздача моделей
  удаления фона (см. §9).
- **fonts.ts**: список семейств шрифтов — `fc-list` (Linux/mac) или
  PowerShell + System.Drawing (Windows), с кэшем и фолбэком.
- **settings.ts**: JSON-настройки (язык, historyMb, SAM-модель и т.д.);
  ключ polza.ai шифруется `safeStorage` (плэйнтекст-фолбэк, если ОС не
  поддерживает).
- **sidecar.ts**: жизненный цикл Python-процесса — venv в
  `~/.local/share/slojka/venv`, спавн `--port 0`, handshake-строка
  `SLOJKA_READY {"port":…}`, Bearer-токен, health-poll, авторестарт с
  backoff, статусы absent/installing/starting/ready/error, прогресс
  установки в UI. IPC-прокси всех polza/SAM вызовов.
- **mcpBridge.ts**: WS-сервер на 127.0.0.1 со случайным портом и токеном
  (`~/.config/slojka/mcp-bridge.json`); форвардит вызовы инструментов в
  renderer (`onMcpCall`/`mcpResult`).
- **ptyHost.ts**: встроенный терминал. Нюансы, выясненные в бою:
  - node-pty — optionalDependency и **исключён из бандла** main-процесса
    (`rollupOptions.external`), иначе ломается его внутренний
    `require('pty.node')`; не собрался — панель честно показывает ошибку
    и инструкцию для внешнего терминала;
  - POSIX: шелл запускается **без `-l`** (логин-профиль пользователя
    может задерживать старт claude, напр. на десятки секунд); `~/.local/bin` и
    `~/.npm-global/bin` добавляются в PATH явно. Windows: `cmd /k claude`,
    в PATH добавляется `%APPDATA%\npm`;
  - прокси (`HTTP_PROXY`/`HTTPS_PROXY`, верхний и нижний регистр) берутся
    из **настроек** (⚙ → Сеть); пустое значение — переменные не задаются;
    дефолт локальных прокси действует только на Linux;
  - команда: `claude || exec $SHELL` (нет claude — обычный шелл);
  - `.mcp.json` с сервером slojka генерируется в рабочей директории
    терминала перед стартом;
  - события pty шлются только в живой webContents (isDestroyed-проверки) —
    выход с открытым терминалом не сыплет «Object has been destroyed»;
  - все pty-сессии прибиваются в before-quit (хвостов процессов не остаётся).

## 6. Форматы файлов

- **`.slojka`** — zip (fflate) в духе OpenRaster: `mimetype`,
  `manifest.json` (полная JSON-модель), `data/layer-<id>.png` (пиксели),
  `data/mask-<id>.png`, `data/source-<id>.png` (оригиналы smart-слоёв),
  `thumbnail.png`. Round-trip побайтно проверяется смоуком (0 расхождений
  композита).
- **ORA** — экспорт и импорт (stack.xml, слои PNG).
- **PSD** — импорт через ag-psd: слои/группы (разворачиваются)/маски/
  blend-режимы/текст best-effort, отчёт о потерях.
- **Экспорт**: PNG / JPEG / WebP (композит), ORA.
- **Кисти**: импорт `.kpp` (Krita) и `.abr` (Photoshop) — см. §4.5.
- **Промты**: `~/.config/slojka/prompts.json` (CRUD, теги, поиск).
- **Автосейв**: снапшот `.slojka` в пользовательских данных.

## 8. SAM 2.1 (локальное AI-выделение)

- Опционально: настройки → «Включить» ставит venv (~15 МБ базовых
  зависимостей), «Установить SAM 2.1» докачивает torch 2.x cu124 (~2.5 ГБ,
  явное согласие с указанием размера) + пиненный sam2. Чекпойнты:
  tiny / small (по умолчанию, ~184 МБ) / base_plus / large, скачивание с
  прогрессом и докачкой.
- Работает в sidecar на **CUDA (NVIDIA)** или CPU; сам редактор рендерит
  на Intel iGPU — VRAM не конкурируют.
- Инструмент «AI-выделение» (A): клик — позитивная точка, Alt+клик —
  негативная, ПКМ по точке — удалить, драг — box. До 3 вариантов маски
  (переключение в панели опций), эмбеддинг изображения кэшируется —
  повторные клики мгновенные.
- Enter/кнопка — в выделение (с ползунком растушёвки), либо в маску слоя.
- Сессия SAM принадлежит документу: сбрасывается при новом холсте,
  открытии файла, переключении/закрытии вкладки (метки не «переезжают»
  на другой документ).

## 9. Удаление фона (локальная нейросеть, без Python)

ПКМ по растровому (в т.ч. smart) слою → «Удалить фон». Полностью локально
и офлайн, работает даже без включённого «Локального ИИ» (Python не нужен).

- **Модель**: ISNet «medium» (~88 МБ) из `@imgly/background-removal` 1.4.5
  (наработки [cut-it-out](https://github.com/Suvink/cut-it-out)) + пакет
  данных `@imgly/background-removal-data` 1.4.5 с npm. Инференс — ONNX
  Runtime Web (wasm, пин 1.17.0 под wasm-сборки из пакета данных; версии
  зафиксированы overrides в корневом package.json, там же — свежие
  zod/lodash от уязвимостей).
- **Ресурсы без CDN**: main регистрирует привилегированную схему
  `slojka-res://` (`resProtocol.ts`; standard + supportFetchAPI + CORS) и
  раздаёт файлы пакета данных: dev — из node_modules, prod — из
  `resources/imgly` (extraResources; `tools/prepare-imgly-data.mjs` кладёт
  туда только модель medium + 4 базовых wasm, ~128 МБ вместо 212).
  CSP renderer расширена: `wasm-unsafe-eval`, `worker-src blob:`,
  `connect-src slojka-res:`.
- **Поток**: `tools/removeBgTool.ts` читает пиксели слоя
  (`readLayerPixels`; для smart-слоя — оригинал через `readSourcePixels`,
  чтобы трансформация осталась без потерь) и отдаёт их в module-worker
  (`removeBg.worker.ts`). Worker: premultiplied → straight → PNG →
  `segmentForeground(..., {output: 'image/x-alpha8'})` → сырая альфа-матте
  в исходном разрешении. Матте умножает все 4 канала premultiplied-пикселей
  (цвета не перекодируются — без потерь), результат уходит обратно.
  Модель после первого запуска остаётся в памяти worker'а — повторные
  вызовы без повторной загрузки.
- **Запись с undo**: `engine.replaceLayerPixels(id, px)` — обычный слой
  (PixelPatch before/after, как у заливки); `engine.replaceSourcePixels`
  — оригинал smart-слоя + `renderSmart` (undo восстанавливает оригинал,
  трансформация не трогается). Если за время инференса слой удалили,
  растеризовали или сменили документ — методы отвечают false, результат
  не применяется (тост «слой изменился»).
- **UI**: пункт меню блокируется на время работы (`bgRemovalLayerId` в
  editorStore), прогресс — тосты (загрузка модели при первом запуске,
  готово/ошибка). Инференс на CPU (wasm SIMD, один поток): секунды.
- **Тесты**: самотест 5п (замена пикселей слоя и оригинала + undo);
  сквозной этап смоука `SLOJKA_SMOKE_REMOVEBG=1 npm run smoke` — синтетика
  (круг на светлом фоне) проходит весь стек протокол→wasm→модель→слой,
  проверяются альфа угла (<30) и центра (>200).

## 10. Хаб генерации polza.ai

- Ключ API в настройках (safeStorage). Один POST `/api/v1/media`
  `{model, input, async:true}` + поллинг; список моделей
  GET `/api/v1/models?type=image`.
- **Модели по умолчанию** (реальные id из документации polza.ai):
  Nano Banana (google/gemini-2.5-flash-image, -3-pro-image-preview,
  -3.1-flash-image-preview), Seedream (bytedance/seedream-4.5, -5-lite,
  -4, seedream), GPT Image (openai/gpt-image-1.5, gpt-5-image,
  gpt-5-image-mini, gpt-5.4-image-2), Flux (black-forest-labs/flux.2-pro,
  -flex), Grok (x-ai/grok-imagine-image), Qwen (qwen/image) + произвольный
  id вручную; апскейл — topaz/image-upscale (×2/×4).
- **Очередь в sidecar**: SQLite `~/.local/share/slojka/jobs.db` —
  переживает перезапуски; поллинг 2→30 с с backoff, таймаут 15 мин,
  до 3 параллельных задач, отмена; скачивание результата с таймаутом
  10 мин (CDN хранит 7 дней — качаем сразу в локальный кэш); base64
  вложения вычищаются из БД после создания задачи (jobs.db не пухнет);
  `remove` (отмена + удаление кэша + строки) и `clear_finished`.
- **Стоимость**: `cost_rub` по каждой задаче и сумма за сессию.
- **Удалить/заменить объект**: работает по выделению (SAM или любой
  инструмент). В модель уходит **вся картинка** с **красной обводкой**
  выделения (граница по порогу >32 — работает и на растушёванных масках;
  белая подложка + красные диски радиусом max(2, min(w,h)/300)); промт
  просит удалить/заменить содержимое контура, убрать сам контур и
  сохранить всё остальное «пиксель в пиксель». Результат вставляется
  **всей сценой** новым слоем под размер холста (не кусок — чтобы не было
  рассинхрона, если модель тронула что-то за пределами выделения);
  расхождение пропорций >2% — равномерное cover-заполнение с тостом.
- **Фотобаш** (кнопка 🎬): весь видимый холст сводится в одну картинку и
  уходит выбранной модели с большим английским промтом professional
  photobash + matte painting (единая камера/свет/материалы, полный
  overpaint, негативные ограничения против «коллажности»); описание сцены
  из поля промта подставляется в секцию SCENE. Aspect ratio — ближайший к
  холсту; результат вставляется всей сценой под размер холста (как у
  удаления/замены объекта), kind `photobash`.
- **Автовставка**: задача привязана к вкладке (`watchedJobs`); по
  завершении результат сам вставляется слоем — но только если активна
  исходная вкладка (иначе тост-уведомление). Поллинг живёт на уровне
  приложения (работает при закрытой панели). Выделение снимается при
  вставке. Aspect ratio запроса подбирается ближайший к пропорциям холста.
- Панель ИИ: модель (имя + id + свой), промт с библиотекой промтов,
  aspect ratio, количество, генерация/апскейл/удалить/заменить, список
  задач (статусы, стоимость, ✕ отмена/удаление, «Очистить завершённые»,
  tooltip с моделью); поле промта не сжимается при длинном списке задач
  (flex-shrink управляется, список скроллится).

## 12. Производительность и лимиты

- Слои — текстуры GPU; новый холст по умолчанию 2048², потолок 8192²,
  предупреждение от 4096².
- Большие радиусы размытий — даунсемпл (см. §4.4); кэш размытий на слой.
- История — бюджет 256 МБ (настраивается), пиксельные патчи сжаты deflate.
- Муравьи — 10 к/с; рендер только по инвалидации; NEAREST на зуме ≥3×.
- Редактор может рендерить на iGPU, SAM — на дискретной NVIDIA (CUDA):
  раздельные бюджеты VRAM.
- Процессы: sidecar и pty-сессии гарантированно завершаются при выходе
  (проверено по остаточным процессам).

## 13. Тестирование и верификация

- `npm run smoke` — сборка + Electron со скрытым окном: WebGL2-инфо
  (детект SwiftShader), ~30 GL-самотестов движка, round-trip `.slojka`,
  клипборд-хоткеи (с переносом стилей), smart-слой, скриншот UI.
  С `SLOJKA_SMOKE_REMOVEBG=1` — плюс сквозной тест удаления фона
  (реальный инференс, лимит смоука растягивается до 180 с).
- `npm test` — vitest: паритет i18n, утилиты стилей текстовых фрагментов
  (нарезка/наложение/слияние/сдвиг диапазонов).
- `npm run typecheck` — TS strict во всех workspace.
- `npm run audit` — уязвимости зависимостей.
- Python: py_compile + ad-hoc тесты очереди (remove/clear_finished/
  _strip_media) в venv.

## 14. Известные ограничения (осознанные)

- Отложено из v1: корректирующие слои, полные динамики кистей .abr/.kpp,
  вектор/фигуры/градиенты, text-on-path, цветовые профили кроме sRGB,
  экспорт PSD.
- Код кроссплатформенный (платформенные ветки: шрифты, venv-пути, шелл
  терминала, пути данных через SLOJKA_DATA_DIR, mcp-bridge по appData;
  win-цель nsis в electron-builder), но на реальной Windows-машине не
  прогонялся: нужны пересборка node-pty под Windows-Electron и смоук.
- Undo штриха, сделанного **после** изменения размера холста, при
  дальнейшем откате может лечь мимо (патчи не пересчитываются под сдвиг);
  откат до состояния перед resize корректен полностью.
- Тени/свечение считаются в полном разрешении R8 — на радиусах ~100 при
  перетаскивании возможны подлагивания (кандидат на даунсемпл-схему).
- Прилипание при трансформации — к краям/центру документа, не к другим
  слоям.
- Старые `.slojka` со spread в долях 0..1 после перехода на пиксели
  требуют выставить «Размер» заново.
- Мультирезультатные генерации автовставкой добавляют все картинки
  слоями стопкой.
